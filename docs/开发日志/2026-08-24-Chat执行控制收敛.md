# 2026-08-24：Chat 执行控制收敛

## 决定

普通 Chat 收敛为 `DIRECT / CONFIRM / BLOCK`：低副作用读取和验证直接执行；所有允许的源仓库写入与可解析的高影响操作进入既有 Permission/Trusted Diff 确认；无法由普通确认安全覆盖的操作直接阻断。

原 Chat → `ISOLATE` → Workspace 自动升级不再作为主路径。它会让用户在隔离副本完成后停在没有受控回源能力的断点。Plan、Workspace、Managed Run、Validation、Patch、Report 和 Run Event 保留为显式高级/实验能力，未删除。

## 已完成

- `ExecutionControlPolicy` 的控制集合改为 `BLOCK > CONFIRM > DIRECT`；
- 依赖清单、lock、迁移、CI/部署配置、`--fix`、代码生成与可解析多文件改动改为带完整原因和证据的 `CONFIRM`；
- 删除、移动/重命名和既有危险 Shell/路径/发布规则为 `BLOCK`；
- Chat 不再创建 Workspace、Run 或读取隔离产物；
- 旧 Session 的 pending isolate 请求恢复后明确冻结，绝不自动执行或转换为源仓库写入；
- 普通 Chat 不再内嵌 Plan 交互，独立高级 CLI 保持兼容。

## 未做

未实现 Patch Promotion。高级 Managed Run 的 Patch 仍仅供审查，`git apply`/`git am` 等通用回写会被阻断；未来需要独立设计可审查回源能力及其快照复核、确认、恢复和审计。
